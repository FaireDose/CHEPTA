# 2026-11-06-02: proposal 0018 reopened; SRK/PR + gE (MHV1) built and compared with the k_ij fits

## What the maintainer decided (2026-11-06, relayed by the coordinating session)

"yes reopen 0018". Build it: MHV1 (the PSRK form) with SRK and PR, with NRTL pairs fitted inside the mixing rule to
the same ThermoML high-pressure data (CO2 + water, CO2 + methanol, and H2, CO and CH4 + methanol). Name it "SRK/PR +
gE (MHV1)", never PSRK. Test it against thermo's PSRK class run with CHEPTA's gE. Report the same errors as for the
k_ij fits, so the maintainer can compare; if it is not better than k_ij = a + b/T, say so plainly.

## Why (Privat and Jaubert 2023)

The review was downloaded by the maintainer and read by the maintainer and the coordinating session on 2026-11-07
(TO_DOWNLOAD.md no. 8, now under Done; proposal 0018, "Why a gE rule where k_ij(T) falls short"): R. Privat,
J.-N. Jaubert, Fluid Phase Equilib. 567 (2023) 113697, doi 10.1016/j.fluid.2022.113697, open access, CC BY 4.0.

- Section 3.4, p. 8: "k_ij(T) coefficients cannot accurately model the most complex mixtures involving polar and
  associating compounds".
- Eqs. (25)-(27), p. 8: EoS/gE mixing rules are equivalent to a k_ij(T, z) ("the use of, e.g., MHV1 MRs do not change
  anything").

## What was built

- **The rule** (`src/thermo/eos/mhv1.js`): MHV1 in the PSRK form of thermo's `PSRKMixingRules` (u = 1.1).
  - A = −ln((u + d1)/(u + d2))/(d1 − d2). For SRK this is thermo's ln(1.1/2.1) = −0.646627; for PR it is −0.57771,
    by the same expression (CHEPTA's derivation; no published PSRK constant for PR).
  - The fugacity coefficients use the analytic partial molar form of the rule.
  - The temperature derivatives of g^E are taken numerically, so H, S and Cp are complete.
  - It plugs into `cubic.js` as an optional mixing rule (`opts.mixing`).
- **The system**: `system({ components, model: "SRK" | "PR", mixing: "MHV1" })`, named "SRK + gE (MHV1)" or
  "PR + gE (MHV1)" in `info.method`. Each pair's NRTL parameters come from the first of these that exists:
  1. a set fitted inside the rule (`src/data/mhv1.json`);
  2. the pair's NRTL set of the databank (the low-pressure gE parameters carried into the rule, the purpose of a gE
     rule);
  3. otherwise: a light gas (or methane) with a polar liquid is **refused**, as the proposal's item 3 says; any other
     pair takes g^E = 0, with a warning.

  `mixing: { rule: "MHV1", nrtl: { a, b, alpha } }` gives the matrices directly (used by the fitting script).
- **The fits** (`validation/fit_mhv1_high_pressure.mjs`): the k_ij fits' points, weights (equal per article), window
  (T ≤ 400 K, P ≤ 20 MPa), objective and gate (5 % AAD in P, every point with a bubble pressure). NRTL
  τ_ij = a_ij + b_ij/T in both directions (four parameters), α = 0.3 (this project's choice), Nelder–Mead from two
  starts. Results go to `validation/data/eos/mhv1_fits.json`; fits within the gate go to `src/data/mhv1.json`.
- **The checks**:
  - `validation/python/reference_mhv1.py` has two parts:
    1. CHEPTA's Python cubic with the rule: g^E from thermo's NRTL, ln φ from the numerical derivative of n·A_res,
       h_R from the numerical T-derivative;
    2. for SRK, thermo's `PSRK` class with the same NRTL parameters and a Mathias–Copeman alpha set to Soave's,
       compared on a, da/dT, d²a/dT², Z_L and h_R.
  - `test/eos-mhv1.test.js` holds the engine to these references at 40 states: P within 1e-4, ln φ within 1e-5,
    h_R within 1e-4; and a, da/dT, d²a/dT² against thermo within 1e-6, 1e-5, 1e-4. Where printed, the agreement was
    about 1e-8. The test also checks that every recorded error is the engine's.

Plainly:

- **For the gases in methanol, MHV1 is better than the k_ij** (bold).
  - H2 + methanol: from 17-21 % to 5.7 % in P.
  - CO2 + methanol: from 7.1-7.3 % (a + b/T) to 5.6 %.
  - CH4 + methanol: from 9 % to 6.3 %.
  - CO + methanol: from 4.6-4.9 % to 2.6-2.7 %.
  - Only CO + methanol is within the 5 % gate, so it is the only pair written to `src/data/mhv1.json`. H2, CO2 and
    CH4 + methanol miss the gate by 0.6-1.3 points.
- **For CO2 + water, MHV1 is not better than k_ij = a + b/T.**
  - PR: 13.1 % against 13.8 % in P, 9.2 % against 10.2 % in solubility.
  - SRK: 16.0 % against 15.3 % in P, the same 11.1 % in solubility.
  - Only the vapour composition improves (y: 0.004-0.006 against 0.007-0.008).
  - With a single NRTL pair (α = 0.3, τ = a + b/T) the rule does not capture what a + b/T misses. The PR fit's
    parameters (a_12 = 13.0, b_12 = −2989 K) also suggest a flat objective rather than a clear optimum.
- In the first version of this pull request, the pairs outside the gate were not written, so MHV1 refused them. The
  maintainer's answers of 2026-11-07 (below) changed that.

## Differences from the proposal's text

- Alpha: Soave's, as in today's SRK and PR, not Mathias–Copeman from ChemSep (proposal item 2; left for a later
  step).
- g^E: NRTL only (no Modified UNIFAC 2.0, UNIQUAC or Wilson in the rule yet; case 1 of the proposal is not built).
- Fitting: a script of its own, not `fit_parameters.py`. No test against held-back articles (step 3), because every
  article is in the fit.
- My data (step 4) is not built.

## Choices for the maintainer (first version; answered on 2026-11-07, below)

1. **Write H2, CO2 and CH4 + methanol** inside MHV1 with a fit-quality known issue: 5.6-6.3 % in P, 5.6-10.2 % in
   solubility. Or keep them out under the 5 % gate.
2. **CO2 + water**:
   - (a) keep k_ij = a + b/T, about the same as MHV1 here;
   - (b) try MHV1 with α fitted as a fifth parameter, or a T² term in τ;
   - (c) CPA (methods track M3), the association model the review points to for water.
3. **The separator** needs every pair. Under MHV1 now: CO + methanol fitted; methanol + water from the databank's
   NRTL set; the gas + water pairs refused. So the separator still runs with PR/SRK k_ij only.

## The maintainer's answers on #214 (2026-11-07, relayed by the coordinating session), and what they gave

   above (5.6-6.3 % in P, 0.6-1.3 points over the gate). SRK's CO2 + methanol set has 1 of its 424 points without a
   bubble pressure, as its warning says.
2. **CO2 + water with NRTL's alpha fitted** (a fifth parameter, from the alpha = 0.3 fit), written only if it beats
   k_ij = a + b/T in P and in solubility with no more points without a bubble pressure:
