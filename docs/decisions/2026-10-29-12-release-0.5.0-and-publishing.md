# 2026-10-29-12: version 0.5.0, and the version taken from the release's tag

The maintainer published the GitHub release `v0.5.0`; the Publish workflow failed ("Release v0.5.0 does not match
package.json version 0.4.0"). The maintainer: "failed to publish on npm. this always happens, try to fix it good and for
all".

## Why it kept failing

The workflow required the version to be bumped by hand, in a pull request, before the release: `package.json`,
`package-lock.json`, the README's status line and every CDN link (`chepta@x.y.z`) in the README, the examples and the AI
instructions. The release of 0.2.2 failed for that, 0.4.0 for a tag typed `v.0.4.0`, and 0.5.0 because the bump was not
made. The test meant to keep the CDN links in step looked for the old name (`fugacity@`), so it checked none of them.

## What changed

- `scripts/set-version.mjs`: sets the version in all those places at once (`node scripts/set-version.mjs 0.5.0`); it
  accepts the tag as people type it (`v0.5.0`, `V0.5.0`, `v.0.5.0`) and refuses anything that is not a version.
- `.github/workflows/publish.yml` (same file name: npm's trusted publisher names it):
  - the version comes from the release's tag; the workflow runs `set-version.mjs` with it before the build and the tests,
    so the package, its README and its CDN links say the tag's version;
  - "Run workflow" by hand takes a version typed in its box, or the one in `package.json` when the box is empty;
  - it still stops, with a clear message, when the version is already on npm;
  - a last job writes the version back to `main` (a push, or a pull request "Version x.y.z" where `main` does not accept
    a push from the workflow), so the repository says what npm has.
- `test/versions.test.js` checks every `chepta@` link (and the old `fugacity@`), the lock file, and the tag forms, with
  the same list of files as the script; design documents and decision records keep the versions they mention.
- This pull request sets the version to 0.5.0 (`main` had 0.4.0).

## How to release from now on

1. Publish a GitHub release whose tag is the new version (`v0.6.0`).
2. Approve the staged version on npmjs.com with two-factor authentication (chepta, Staged Packages).

Nothing to bump by hand. For 0.5.0, whose release already exists: after this pull request is merged, Actions, "Publish to
npm", "Run workflow" (box empty: it takes 0.5.0 from `package.json`), then approve on npmjs.com.
