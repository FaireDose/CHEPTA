# 2026-11-11-03: release 0.6.0, and the version written back to main

## What happened

The maintainer published the GitHub release `v0.6.0` on 2026-11-11. The Publish workflow (run 42984203733) verified
the build and the full test suite, attached the skills and staged `chepta@0.6.0` on npm. Its last job, `sync`, failed:

- `main` refuses a direct push ("Changes must be made through a pull request", "Required status check \"test\"");
- the job then pushed the branch `version-0.6.0` but could not open the pull request: "GitHub Actions is not permitted
  to create or approve pull requests".

Before the release, the coordinating session ran the workflow's own check on `main` at 5112c71 with the version set to
0.6.0: 1554 tests, 1553 pass, 0 fail, 1 known TODO.

## What changed

- The coordinating session opened the pull request "Version 0.6.0" from `version-0.6.0` (FaireDose/CHEPTA#223), to
  merge after the staged version is approved on npmjs.com (its CDN links name `chepta@0.6.0`).
- `.github/workflows/publish.yml`, job `sync`: where `main` refuses the push, the job pushes `version-x.y.z` and ends
  with a notice and a line in the run's summary that link to the pull request to open, instead of failing. Letting
  Actions open pull requests would not help: a pull request opened with the workflow's own token does not start the
  `test` check that `main` requires.

## How to release from now on

1. Publish a GitHub release whose tag is the new version.
2. Approve the staged version on npmjs.com (chepta, Staged Packages) with two-factor authentication. The Approve
   button stays grey while npm is still validating the staged version (docs.npmjs.com/staged-publishing): reload after a
   few minutes. From a terminal: `npm stage list chepta`, then `npm stage approve <stage-id>` (npm 11.15 or newer).
   On 2026-11-11 the button was grey at first; the maintainer approved 0.6.0 later the same morning.
3. Open the pull request "Version x.y.z" from the link in the workflow run's summary, and merge it.
